## 같은 커밋을 새 폴더에서 재현하는 기록

1. 원래 작업 폴더를 보존합니다. 기존 파일·Git 기록을 지우거나 덮어쓰지 않습니다. 원래 저장소의 URL·브랜치·40자리 커밋을 직접 기록합니다.
2. 빈 새 폴더를 준비합니다. GitHub 저장소는 해당 저장소를 clone한 다음 기록한 커밋으로 전환합니다. 저장소를 아직 올리지 않은 경우에는 학생이 보유한 로컬 원본을 대상으로 하는 `git clone` 또는 과제에서 허용한 수료 패키지 내보내기 절차를 사용합니다. 실제 저장소 주소·폴더 경로·커밋 값이 확인되기 전에는 이 문서가 구체적인 명령을 만들어 주지 않습니다.
3. 새 폴더가 기록한 바로 그 커밋인지 확인하고 환경을 기록합니다. `package.json`은 `24.19.0`을 기준으로 선언하지만 시작 도구는 22~24를 허용하므로, 실제 `node --version`과 사용한 버전을 따로 적습니다.
4. 21단계 학생 설명서의 순서에 따라 런타임 확인·필요한 런타임 설치·실행·브라우저 확인·종료·재실행을 직접 수행합니다. 현재 문서에 없는 의존성 설치 절차를 추측해 추가하지 않습니다. 기존 폴더의 인증·설정 파일을 무작정 복사하지 않습니다. 기본 실행 도구가 사용자 프로필의 프로젝트별 계정 연결 준비를 수행할 수 있다는 점도 고려하고, 실행 중 실제로 확인한 사항만 기록합니다.

## 데이터 보존·백업·복원 계획과 한계

### 프로젝트 파일과 Git 기록

- 원래 작업 폴더는 재현 폴더와 분리해 보존합니다. 새 폴더에서만 재현 절차를 수행합니다.
- 제출 대상 커밋과 브랜치·저장소를 기록하고, 기존 변경사항이 있으면 먼저 확인합니다. `reset`, `clean`, 삭제 또는 기존 작업 덮어쓰기를 복구 절차로 사용하지 않습니다.
- 복원은 보존한 원래 폴더와 기록한 커밋을 기준으로 별도 작업 폴더에서 수행합니다. 이 절차가 새 폴더의 수정 내용을 자동 백업한다는 뜻은 아닙니다.
- 보존 확인 근거에는 원래 폴더가 남아 있는지와 원래 Git 기록이 유지됐는지를 적습니다. 실제 확인 전에는 보존 성공으로 표시하지 않습니다.

### 인증·설정과 실행 중 데이터

- 원래 환경의 인증·설정 파일을 재현 폴더로 무작정 복사하지 않습니다. 비밀값과 인증 파일을 Git 커밋·캡처·이 문서에 기록하지 않습니다.

## 같은 기준 커밋의 버전 이력

서로 다른 커밋에서 얻은 통과 결과를 합쳐 최종 버전 전체가 성공했다고 표시하지 않습니다. 문제가 수정돼 새 커밋이 만들어지면 새 커밋을 기록하고, 최종 결과는 그 새 기준 커밋에 대해 다시 확인한 내용으로 정리합니다.

| 기록 순번 | 버전 | 40자리 커밋 | 확인 범위·모드 | 확인 결과 | 확인 시각·근거 |
|---|---|---|---|---|---|
| 최초 기록 | `0.2.21` (package.json 선언; 릴리스 인증 아님) | 미기록 | 코드·문서 원문 대조만 | 새 환경 실행 미확인 | 코드에서 읽은 정보만 확인 |
| 새 환경 재현 | 미기록 | 미기록 | 미기록 | 미확인 | 미기록 |

문서나 코드 수정이 재현 후 새 커밋을 만들면, 이전 커밋에서 관찰한 결과를 새 커밋의 실행 결과로 바꾸지 않습니다. 최종 제출 커밋과 재현 대상 커밋이 같은지 확인하고, 다르면 그 차이를 명시합니다.

## 현재 결론

- 코드·문서에서 읽어 확인한 범위: 위의 버전·Node 기준·실행 스크립트와 문서상 입력 계약.
- 새 환경에서 직접 실행한 결과: **미확인 — 아직 실행 기록이 없음.**
- 모의 데이터 결과: **미확인 — 아직 demo 실행 기록이 없음.**
- 실제 시스템 연결 결과: **미확인 — 실제 연결 실행 기록이 없음.**
- 실제 보안 조치 집행: **준비되지 않음 — 완료로 표시하지 않음.**
- 최종 커밋·제출 상태: 저장소 URL·브랜치·40자리 해시가 확인되지 않아 **미기록**.
- 버전 상태: **검증 중**. 22단계 기록만으로 운영 인증 또는 자동 `v1.0` 인증을 주장하지 않습니다.

## 학생 직접 확인 — 다음 한 번의 작업

**확인 1:** 원래 작업 폴더와 기존 기록이 그대로 남아 있는지 확인합니다. 이때 저장소 URL, 브랜치, 제출하려는 40자리 커밋과 원래 폴더 경로도 직접 확인해 위 표에 기록합니다. clone이나 재현 실행은 이 값들이 확인되기 전에는 시작하지 않습니다. 기존 폴더·Git 상태를 확인하는 PowerShell 명령은 학생이 실제 원래 저장소의 Git 최상위 폴더에서 실행해야 합니다. 이 도구는 PC에서 해당 명령을 실행하거나 경로·값을 확인하지 않았습니다.
